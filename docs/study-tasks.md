# 每日小任务管理

当前没有已启动的学习任务。本轮只是框架整合，不将计划目录算作完成练习。
最多保留一个 active 任务；备选主题留在学习映射，不预先建一批任务文件。

## 工作方式

1. 用户提供今天的章节、数值疑问或 GitHub 项目；先读学习映射与已有代码。
2. 提出一个 60–120 分钟能推进的具体问题，明确停止点、输入输出、单位和验证方法。
3. 用户编写核心代码；协作者按 AGENTS.md 的分阶段教学规则给提示、解释错误并设计检查。
   完整参考实现仅在明确要求、实际尝试后需要对照或任务确实需要时提供，说明原因并限制范围。
4. 若尚未完成，保留 active 或 paused 和下一步；完成后记录实际测试、解释与 commit/PR。
5. 案例详细笔记按需放入其 `notes/`；实际活动摘要写入 [学习进度](learning-progress.md)，
   本文件只维护任务状态和证据链接，不重复复制整个学习日志。

提出任务前查实际章节、进度和代码；掌握程度不清楚时先做一个简短诊断。
任务需包含关键科学概念、参考项目（无合适项目可写不适用）和完成标准。
明确的仓库管理、配置、测试及文件整理请求直接执行，不强行变成教学问答。

## 开始任务时复制这一条记录（现在不实例化）

```text
ID / 日期：YYYY-MM-DD-short-topic（当天本地日期）
进度：active | paused | done（不是代码成熟度标签）
来源：教材、版次、章/节/页或上游 URL + commit；未知项明确写待核对
归属：study-map 中的唯一案例路径
问题与目标：一句话；预计 60/90/120 分钟
假设/方程/单位：只列本任务所需
输入 → 输出：参数范围和预期量
用户实现：一个函数/离散步骤/分析；协作者只给必要提示
验收：解析关系、手算一步、守恒或明确误差指标与容差依据
停止点：时间用尽时保留什么可检查的产物
实际证据：命令、环境、结果、错误原因和解释；没有执行就写未执行
代码状态：Planned | Implemented | Tested | Validated（注明比较对象和范围）
成果：代码/笔记链接、commit / PR
下一步：一个最小动作
```

done 表示本次约定的学习目标完成，不自动表示物理 Validated。
不为填任务记录而伪造命令、数值或阅读进度。
